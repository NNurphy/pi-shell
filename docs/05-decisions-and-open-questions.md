## A. 已定决策

| ID | 决策 | 理由 | 代价 |
|---|---|---|---|
| **D-01** | **RPC + 自建前端**（不用扩展形态 / SDK / fork） | 跑已装的官方 pi；独立子进程；唯一能桥接扩展弹窗；协议 1.3→1.5 的 33 个命令零变化（实测 diff） | 自写桥与前端；TUI 专属能力不可用 |
| **D-02** | **不做**工具调用审批层 | pi 官方无沙箱、不逐条审批；造一层会给人错误安全感 | 壳与终端同权限（已告知并接受） |
| **D-03** | **单个 pi 子进程 + `switch_session`**；**换工作区时重启子进程** | 多进程写同一 JSONL 更危险；RPC 无 `set_cwd`、`new_session` 无 cwd 参数（实测） | 切工作区 1–2s，且**新会话为空会话**（未发消息前不落盘）；同一时刻只能一个会话在跑 |
| **D-04** | **无认证**，仅绑 `127.0.0.1` | 与 TUI 同信任级 | 本机任意进程可访问 |
| **D-05** | 前端**原生 ESM，无框架无构建** | 依赖面为零，便于审阅与长期维护 | 复杂交互手写成本高 |
| **D-06** | **文档先行**：复审通过才写代码 | 避免口径混乱 | 进度延后 |
| **D-07** | 边界已批准（2026-11-03）：不做审批层；**接受"双端同开无法技术阻止，仅提示 + 备份"** | Owner 答复 Q-1/Q-2 通过 | 风险转为"已告知并接受" |
| **D-08** | **不探测"会话是否被 TUI 占用"**，改为"打开前强制提示（勾选一次）+ 备份 + 恢复指引" | 实测：pi 1.5.0 **不加锁**（`session-manager.js` 无 lock 调用）；写盘为 append；`_rewriteFile()` 仅 3 处（空文件打开/版本迁移/分支新文件）；真实风险是**追加交错半行被静默跳过、分支分裂、双份压缩摘要** | 无法阻止误操作，只能提示；风险由用户承担 |
| **D-09** | 换工作区 = 重启子进程（`POST /api/workspace`） | RPC 无 `set_cwd`，`new_session` 不接受 cwd | 中断当前任务（streaming 时拒绝切换） |

| 轮次 | 原说法 | 结论 |
|---|---|---|
| 之前 | "扩展形态可以桥接扩展弹窗" | ❌ 错。扩展的 `ctx.ui` 交给宿主 TUI，第三方无法拦截 |

| 早期 | "压缩/分支时整文件重写"作为双开主危害 | ❌ 机制错（10 复核 R-04）。实际：append 为主，重写仅 3 处；主危害是半行被跳过 / 分支分裂 / 双份摘要 |
| 早期 | A-04"页面消息 id 出现在文件中"、断线按 `message.id` 去重 | ❌ 错（R-02）。`message` 无 `id`；改用 entry id（`get_entries`） |

| 早期 | V-03 退路"用 `where pi` 的绝对路径" | ❌ 无效（R-09）。实测 `pi`=ENOENT、`pi.cmd`/绝对路径=EINVAL |
